# Technical Writing

Make the document accurate, understandable, and usable for its intended reader.

1. Infer audience, language, genre, and whether the task is drafting or polishing from the request and supplied material. Preserve the requested scope.
2. For drafting, ground behavior and examples in the supplied notes, repository, or relevant official documentation. For polishing, preserve claims, conditions, uncertainty, numbers, names, code, and identifiers.
3. Lead with the reader's task or the report's conclusion. Use ordered steps for procedures, tables for comparisons, and headings where they aid navigation.
4. Make procedures executable: state prerequisites, working directory, placeholders, commands, and the expected result. Distinguish verified output from an illustration.
5. Check consistency between prose and code. Fix a demonstrated technical error only when correction is in scope; otherwise flag it separately. Redact actual secrets in examples.
6. Verify changed links, anchors, identifiers, and command examples as appropriate. Report any validation that could not be performed.

## Korean and English editing

- Keep one term for each concept and explain unfamiliar abbreviations on first use.
- Prefer concrete subjects and verbs. Remove empty hype and repeated setup phrases.
- In Korean, replace awkward nominalizations and translation-like expressions only when the meaning stays intact.
- Preserve modality: “may fail” must not become “fails”; “권장한다” must not become “반드시 해야 한다”.
- Keep useful lists, code blocks, and tables. Do not force every paragraph into bullets or erase structure to make prose sound natural.
- Do not invent benchmarks, API behavior, quotes, or citations to make the text more persuasive.

Return the requested document or edit directly. Create intermediate files, change-rate scores, or multiple review passes only when they serve the requested deliverable. Publishing or sending the document is a separate action requiring authorization.
